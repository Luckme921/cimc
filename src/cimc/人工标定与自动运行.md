# 人工标定一次，随后自动处理 ABB 多条请求

启动命令（现场需先确认 ABB 程序处于安全调试状态）：

```bash
source /opt/ros/humble/setup.bash
source /home/mini/x86_ros2_ws/install/setup.bash
ros2 launch cimc camera_weld_operator_abb.launch.py workflow_mode:=manual
```

人工模式启动后，ABB TCP 接收节点先监听 `192.168.3.100:45000`，以免机器人因连接失败退出。此时**不接受**拍照任务：过早的 `START_CAPTURE` 会收到 `TRAJECTORY_ERROR:OPERATOR_NOT_READY`，不会排队或复用旧拍照位姿。机器人程序应在操作员完成确认、终端依次出现 `Camera ready`、`Hand-eye bridge ready` 和“任务协调节点已就绪”后才发送拍照请求；TCP 连接成功不等于系统允许拍照。现有 RAPID 程序如只会连接后立即发送、且不识别上述错误帧，应由机器人开发者增加等待/重试逻辑。

不要与旧 `camera_weld_handeye_abb_test.launch.py` 同时运行：两个完整链路会争用相机、ABB TCP 监听端口并重复处理话题。人工界面的实时查看器以及两个 ABB launch 中的相机节点，仅在各自子进程设置 `NO_PROXY=*`，让厂商 SDK 对局域网相机直连；不会改动系统或其他进程的代理设置。若相机未上电，界面预览只尝试 3 次以便较快返回，ROS 相机节点仍按 `camera.yaml` 的发现重试参数运行。

操作窗口提供两条路径：

1. 已有固定 ROI/偏移，无需修改：直接点“确认配置，启动自动链路”。
2. 需要调节：在“点云与 ROI / 相机成像参数”中可填写深度范围、增益、曝光、帧时间、稀疏帧重拍次数和最小有效深度比例。实时预览用界面当前的五项深度参数，固定网络 true / USB false、最多显示 150000 点以减少画面卡顿；按 S 保存的 PLY 仍是完整点云并保留 SDK 法向量。重拍次数和有效比例仅作用于确认后启动的 ROS 相机节点。点“实时预览相机并画 ROI”，在实时点云窗口中用 T/B/D/K、X/Y/Z、N/M、`[`/`]` 调 ROI；按 S 保存后，点云窗口无需退出，ROI 和 PLY 即自动回填到操作界面；按 Q 退出点云窗口后再点“用当前参数离线预览”。S 的保存目录与 ROS 相机节点一致，默认 `/home/mini/scut_weld_data/pointclouds`。也可选历史 PLY。在“算法与常用参数 / 分类点位偏移”中修改 ROI、算法模式、安全过渡点抬离、圆角间距/点数、四类角工作角和各组点 X/Y/Z 偏移后，点“用当前参数离线预览”。系统会尝试在 VS Code 中打开**算法原生** `operator_preview_序号_result.ply`；独立表格列出 P 序号、特征类型、`position_offset_group`、实际偏移和点来源，支持单点青色高亮。预览历史不会互相覆盖，可反复比对。若 VS Code 未自动打开，可复制表格上方路径手动打开。当前值成功预览后才能确认。

“手眼标定”页显示 OpenCV 4×4 矩阵和刚体有效性检查，可选择另一个现有标定文件，并设置 `matrix_key`、`matrix_direction`、`matrix_translation_unit`。**不会修改矩阵文件内的 16 个数字**；最终确认仅更新 `handeye_bridge.yaml` 对该文件的引用和方向/单位。`tcp_from_camera` 是 TCP←Camera，`camera_from_tcp` 是 Camera←TCP（节点求逆）；不能根据矩阵数值自动判定物理方向。若改变标定文件/方向/单位，必须先人工核对并勾选标定确认。输出坐标系、ABB 发送开关和点数上限在页内只读。离线焊缝 PLY 预览不能证明手眼方向或机器人可达。

S 保存的 PLY 在相机点云目录；离线 CSV/result.ply、`extract_序号.log`、批准记录、配置修改前备份在工作区 `operator_sessions/时间戳/`。离线算法预览读取**当前焊缝参数**和当前选中 PLY；相机实时预览读取**当前相机深度参数**，两种预览都不写正式配置。最终确认才分别对 `src/chishine_camera_ros2/config/camera.yaml`、`src/weld_seam_perception/config/weld_seam.yaml`、`src/cimc/config/handeye_bridge.yaml` 中真正改变的参数定点修改，其他注释和参数保留；各节点确认后启动，分别读取新配置。若焊缝参数或已选 PLY 改变，必须重新离线预览；只改相机或手眼参数且不选 PLY 可确认，但仍需现场检查成像/坐标变换。若完全不改配置且未选择 PLY，可直接确认而不重写 YAML。预览点数若为 0 或超过 ABB 的 100 点上限，不能确认。算法给出的 `WARNING:`（例如偏移后点位低于检测底面）会在复核页和最终确认弹窗显示；此类提示需要人工核对点位，不代表机械臂可达或已经安全验证。

最终确认后默认另开只读“运行状态”窗，显示 ABB TCP 连接状态、`/abb/raw_text` 收到的命令、`/abb/tx_text` 准备发出的轨迹、`/abb/tx_status` 的 socket 发送结果、`TRAJECTORY_ACK`、`/weld_task/status` 任务阶段、`/weld_seam/status` 算法耗时与 `/abb/task_timing` 本次及累计耗时。点击事件可看完整原文；窗口关闭不会停止机器人链路。若不需界面或当前机器无桌面，可加 `show_operator_status:=false`；终端话题 echo 默认关闭，需要逐话题调试时加 `echo_topics:=true`。状态窗**不发布任何控制命令**，`/abb/tx_text` 出现不等于已写入 socket，`/abb/tx_status` 的 OK 也不等于 ABB 已 ACK 或实际执行。

运行阶段只有相机、焊缝提取、手眼转换、任务协调、ABB TCP 接收这 5 个核心节点；人工模式的状态窗是第 6 个只读 ROS 节点。启动前的配置窗不是 ROS 节点。旧的多条 `ros2 topic echo` 均为可选调试进程，默认不启动；焊机、电机和第三方 IP 通道不在此链路运行。相机与算法之间的 ROS 消息只传 PLY 路径，点云文件本体经磁盘传递；因此 SHM 对该段耗时的收益预计有限，算法/采集时间仍是主要指标。

默认 `use_shared_memory:=true` 选择本机安装的 Fast DDS，并令其内建传输使用 `DEFAULT`：同机 ROS 节点优先 SHM，同时保留 UDPv4 发现与跨机诊断回退，**不是 SHM-only**。ABB 与相机的厂商 TCP/SDK 通信不经过 DDS。若现场遇到 DDS 发现或 SHM 权限问题，可在同一 launch 中设置 `use_shared_memory:=false`，恢复继承现场原有 DDS 环境；不要单独修改某个 ROS 进程的 RMW。若现场已有自定义 Fast DDS XML 且禁用了内建传输，本开关不能覆盖该 XML，需要先检查 `FASTRTPS_DEFAULT_PROFILES_FILE`。

固定夹具模式沿用原有 launch 和当前 YAML，不打开人工窗口：

```bash
ros2 launch cimc camera_weld_operator_abb.launch.py workflow_mode:=fixed
```

也可以继续直接用旧命令 `ros2 launch cimc camera_weld_handeye_abb_test.launch.py`。

计时：算法每次输出 `Total time including PLY I/O`；ABB 端到端计时从完整 `START_CAPTURE` 收到起，到轨迹 `sendall` 完成为止，终端显示 `[ABB端到端耗时]`，话题是 `/abb/task_timing`。`/abb/tx_status` 只能说明本机 socket 写入成功，机器人实际 ACK 与执行结果仍应由 ABB 端验证。

人工预览程序独占相机，所以 Q 退出预览后才允许确认并启动 ROS 相机节点。人工模式仅多出启动前配置步骤；运行阶段与旧链路一致。该 launch 不启动焊机或电机节点；但如果 ABB 自己的程序会收到轨迹后运动，仍须由现场人员确认安全模式。
